# e销宝 离线评测报告

> 本报告由 `node scripts/eval.mjs` 生成。评测**不联网、不调用模型**，
> 只覆盖确定性链路（意图打分 → 混合检索 → 转人工判定）。
> 涉及模型生成质量的指标（Grounded Response Rate 的最终表述、Forbidden Claim Rate）
> 需要在线评测，见文末说明。

- 评测时刻：`2026-10-15T02:00:00.000Z`
- 知识库：话术卡 30 张，产品事实 12 条
- 样本数：65 条（其中 3 条为规则类样本，不要求话术召回）

## 核心指标

| 指标 | 目标 | 实测 | 结论 |
|---|---|---|---|
| Intent Accuracy | ≥ 90% | 100.0% | 达标 |
| Phrase Retrieval Recall@3 | ≥ 85% | 100.0% | 达标 |
| Human Handoff Recall | ≥ 95% | 100.0% | 达标 |
| Grounded Response Rate（确定性链路） | ≥ 95% | 100.0% | 达标 |
| Forbidden Claim Rate（确定性链路） | ≤ 1% | 0.0% | 达标 |

- 人工接管误报（不该接管却接管）：13 条
- 置信度分布：p50 = 0.866，p95 = 0.950

## 指标口径

- **Intent Accuracy**：预测意图与标准意图一致的比例。质量兜底类样本（医疗、金融、
  索要他人信息）的判据改为「规则是否成功接管」——这类表达本就不该走话术库。
- **Phrase Retrieval Recall@3**：标准意图出现在 Top-3 召回中的比例。规则类样本计入合格。
- **Human Handoff Recall**：应转人工的样本中，实际被规则判定的比例。这是安全指标，漏报比误报严重。
- **Grounded Response Rate**：至少召回一张已审核话术卡的比例。真正意义上的「有依据」
  还需要模型正确引用，那部分需要在线评测。
- **Forbidden Claim Rate**：确定性链路不经过模型生成，因此结构性为 0；
  真实的禁止承诺拦截效果由 `test/rules.test.mjs` 的单元测试证明。

## 这份报告不能证明什么

评测样本与种子话术卡是由同一份夹具生成的，因此**存在过拟合**：口语化变体
（如「介个东西咋卖」）在开发过程中被补进了卡片示例，指标随之升到 100%。
这证明的是链路可用与门禁有效，**不是**真实通话上的泛化能力。

要得到有意义的泛化指标，必须用**没有参与调参**的真实客户表达复测：

1. 收集 100 条以上真实通话表达（开发计划阶段 0 的交付项）；
2. 用其中 50 条补卡片示例，另 50 条作为留出集；
3. 只对留出集跑本脚本（`--fixtures <path>` 指定留出集）；
4. 留出集上的指标才是可信的泛化指标。

## 在线评测的缺口

以下指标无法离线测量，需要在接入真实模型后按同样样本表复测：

- 模型输出的 `source_cards` 是否全部落在候选集内（结构校验会拒绝越界，但拒绝率需要统计）；
- 模型表述是否引用了事实库之外的数字（`findUnauthorizedNumbers` 的拦截率）；
- 建议延迟 p50/p95；
- 销售的采纳率与主观帮助度。

复测方法：启用插件后在配置页「试运行与评测」粘贴 `fixtures/utterances.json` 的
`utterance` 字段，逐条核对；或调用 `POST /api/cqai-xiaobao/preview`。
