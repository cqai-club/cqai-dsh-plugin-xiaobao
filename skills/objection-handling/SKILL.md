# objection-handling

## 何时使用

客户表达了任何形式的顾虑，包括：

- 价格顾虑："太贵了""有没有便宜点的""预算不够"；
- 适配顾虑："我这个情况能用吗""和我现在用的能配合吗"；
- 效果顾虑："真的有用吗""多久能看到结果"；
- 竞品比较："XX 家比你们便宜/功能多"；
- 服务顾虑："售后怎么做""出问题找谁""能不能退款"。

不确定是不是顾虑时：客户语气里带犹豫、比较、否定、质疑，就按顾虑处理。

## 方法：C 端版 ACRC

```text
承认顾虑 → 澄清原因 → 用已审核事实回应 → 确认是否解决 → 提供低压力下一步
```

五步都要走，顺序不能颠倒。**不要跳过澄清直接回应**——不了解原因就解释，等于自说自话。

### 1. 承认顾虑

一句就够。承认的是"这个顾虑合理"，不是承认"我们贵"或"我们有问题"。

- 可以：`这个确实是要考虑清楚的。`
- 不可以：`你说得对，我们确实比别家贵。`

### 2. 澄清原因

用一个问题把模糊的顾虑变成具体的问题。多数顾虑有两种截然不同的原因，回应方式完全不同：

- 价格顾虑 → 是预算真的超出，还是不确定值不值？是总价高，还是付款方式有压力？
- 效果顾虑 → 是担心没用，还是担心不适合自己的场景？
- 适配顾虑 → 是担心功能不够，还是担心迁移和上手成本？

追问一次即可，客户不回答就按最保守的理解继续。

### 3. 用已审核事实回应

- 先用 `get_product_policy` 取相关权威事实（价格、政策、能力边界、试用、退款条款）。
- 用 `search_phrase_cards` 取该意图下的已审核话术卡，参考表达方式。
- 回应里每条事实都标来源与版本；拿不到依据就说"这个我需要确认后回复你"，不要用常识顶。
- 政策里明确写了不支持的，直接说不支持，不用模糊话绕过去。

### 4. 确认是否解决

问一句"这样说的是你想了解的点吗？"或"这样清楚了吗？"。客户没被说服很正常，不要立刻重复第二轮解释。

### 5. 提供低压力下一步

只允许这类动作：继续了解、看资料、预约演示、申请试用、留下联系方式由销售跟进。

## 分类型处理要点

- **价格**：区分预算问题与价值不确定。不贬低客户预算，不暗示"便宜的都不行"。不用"原价 XX 现在 XX"这类没有政策出处的说法。
- **适配**：先讲适用条件，再讲**不适用条件**。客户的情况确实不适合时，明确说不适合，给出更合适的方向；把不适合的客户推进成交是错的做法。
- **效果**：只说政策中已核实的效果描述，不承诺结果、不给时间点保证、不引用无出处的案例。
- **竞品**：只讲自家已核实的事实和自己的适用场景。不评论竞品价格、不贬损、不传播未经核实的信息。客户追问竞品细节时，说明无法评价别家，回到自己的事实。
- **服务**：退款、售后、配送按政策原文回答。政策未覆盖的，转人工，不自己解释、不给例外。

## 输出结构

```text
顾虑类型：<价格 / 适配 / 效果 / 竞品 / 服务>
客户原话：<转写原文，不改写>
承认：<一句话>
澄清问题：<一句话>
事实回应：<回应话术>
  - 依据：<政策条目 id · 版本 · 生效期>
  - 参考话术卡：<card id>
确认语：<一句话>
下一步：<低压力动作>
do_not_say：<本轮明确不能说的话>
```

对已成功说出的话术，用 `save_coaching_feedback` 记录采纳/修改/跳过；客户未被说服时也记录，标注"未解决"，供复盘。

## 禁止手段（硬边界）

- **虚假稀缺**：编造名额、库存、排期紧张。
- **虚假截止日期**：编造涨价、活动结束、政策到期时间。
- **未授权折扣**：任何没有政策依据的让价、赠品、返现、"我帮你申请"。
- **连续施压**：同一个顾虑反复追问、客户拒绝后继续推、用焦虑或恐吓推动决定。
- **伪造证据**：编造案例、数据、客户评价、来源 id。
- **越权承诺**：效果保证、退款承诺、合同条款解释、赔付方案。

命中任一条就是不合格输出，必须重写。

## 与代码层拦截的关系

转人工判定和禁止承诺拦截由**代码执行**，不由本 Skill 自觉。你的输出会被规则检查：

- 你的建议里出现被拦截的表述时，该建议不会展示给销售；
- 命中人工接管条件时，代码会直接提示转人工，不等你的判断。

因此不要试图"换个说法绕过"禁止清单，也不要在被拦截后换述同一承诺。改写方向只能是：换成有依据的事实、改成提问、或建议转人工。

## 边界与禁止

- 不承诺、不让价、不代表公司做任何决定。
- 不编造政策，不引用未审核或已过期的话术卡。
- 不贬损竞品，不传播未核实的负面信息。
- 不因为客户坚持就放宽边界；客户施压不是放宽规则的理由。
- 客户明确拒绝时立即停止，转向尊重与收尾，并考虑转人工（交给 `human-handoff`）。
- 不处理退款、赔付、投诉、法律与合同的具体问题，一律转人工。
